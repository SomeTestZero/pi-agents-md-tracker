# pi-agents-md-tracker

轻量的 [pi](https://pi.dev) 扩展：用项目根目录的 `AGENTS.md` 做跨会话的项目状态跟踪。

## 功能

- **自动创建**：会话启动时当前目录没有 `AGENTS.md`，自动写入最小骨架（项目概述 / 技术栈与结构 / 常用命令 / 当前进展与状态 + 维护规则），agent 在对话时增量补全各节内容。
- **体积提醒**：`AGENTS.md` 超过阈值（默认 24KB 或约 8k tokens，取先到者）时，会话启动发出 warning 提醒用户让 agent 精简（上下文文件每轮整份注入，过大会持续消耗上下文）。
- **规则自动注入**：若 `AGENTS.md` 存在但不含维护规则标记（如手写的文件），每次对话前自动向系统提示追加一条简短的维护规则，提醒 agent 完成重要改动后更新「当前进展与状态」。

内置于骨架和 `/init` 的维护规则（防流水账/保持精简/subagent 分工）：

- **保持精简**：预计超过 ~150 行时优先删旧信息、合并重复内容，而不是继续追加；细节放代码注释或独立文档，AGENTS.md 里给路径即可。
- **不记流水账**：不逐条罗列会话过程、临时改动、中间状态，只保留当前有效的结论。
- **subagent 规则**：主会话的上下文是稀缺资源，其精炼优先于任务完成速度。凡预计消耗大量上下文的子任务，倾向派 subagent 隔离执行，主会话只保留结论。大规模搜索、批量文件阅读、冗长生成等只是常见例子，并非穷举——是否派 subagent 由 agent 根据任务特点自行评估（如上下文膨胀风险、结果可压缩性），不要只在列举的情形才使用。

防重复：文件含 `<!-- agents-md-tracker -->` 注释标记即视为"已带维护规则"，扩展检测到标记就不再注入（规则已随 `AGENTS.md` 自动加载进上下文）。

## 安装

```bash
pi install git:github.com/SomeTestZero/pi-agents-md-tracker
```

更新：

```bash
pi update --extensions
```

## 使用

自动：进入没有 `AGENTS.md` 的项目目录启动 pi 即可，骨架会自动创建。

手动：

```
/init                        # 调研项目，创建或增量更新 AGENTS.md
/init 重点关注 mod 加载逻辑    # 带补充说明
```

之后正常工作即可，agent 会按维护规则自行更新进展区块；pi 启动时自动加载 `AGENTS.md`，新会话自动获得最新项目状态。
